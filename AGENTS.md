## Core conventions

- **Single authority**: anything that mutates durable decision state flows through the API; console commands call the API, they never mutate directly.
- **Engine-safety guard**: promote/quarantine applies run under the ReviewLoop guard â€” a running engine means HTTP 409 and the request stays pending (retryable). This contract is tested; preserve it.
- **No researchâ†’live shortcut**: DSPy/Strategy Lab produce candidates that reach production only via governed change requests.
- **Governance is the final operational authority**: approval/rejection/risk limits/promotion/quarantine/production activation all route through Governance OS. AI/LLMs/DSPy are reasoning components â€” they may interpret/propose/generate, never place live trades, promote, or modify production risk without governed approval (Â§27). The user interface is a surface of the Control Plane, never a second authority and never the source of truth (Â§28).
- **User strategy lifecycle**: a natural-language description is captured verbatim â†’ canonical Strategy Specification â†’ ambiguity detection â†’ user confirmation â†’ vetting â†’ research â†’ validation â†’ paper â†’ governance â†’ production; failure yields explicit REJECTED/QUARANTINED/NEEDS_REVISION, never silent deletion (Â§27.3â€“27.4, Â§28.5â€“28.8).
- **Docs discipline**: completing any milestone/orphan flips `[ ]`â†’`[x]` in PROJECT_MAP, adds a dated DECISION_LOG row (Accepted/Rationale/Rejected), and keeps README/RUNBOOK/UPDATE-annex in sync.
- **Dashboard honesty**: no fabricated numbers; absent sources render `EmptyState`/`â€”` with the live/mock banner; mocks in `lib/mocks.ts`, APIâ†’UI adapters in `lib/adapters.ts`.
- **One process, one canonical state**: an engine runs *inside* the API process (`/mt5/watcher`, `/paper/engine/start`, `/cex/engine/start`), never as its own scheduled process. A second process owns a second `MarketPlane`, a second `core.state` and a second opportunity board, and the failure is silent rather than loud. `scripts/paper_engine.py` was deleted for exactly this reason â€” do not bring it back.
- **Documented â‰  implemented**: `New Expind dev.md` and the [TECH_STACK] table describe RabbitMQ; there is no `pika`/`amqp` dependency or code path, and the runtime database is SQLite unless `POSTGRES_HOST` is set. Verify a claim against the running system before repeating it (Â§28.4).
