B. PRIORITISED GAPS
====================================================================

P0 — CORRECTNESS / MONEY
 1. Tournament window closes -> enforcement fails open, not closed.   (A6)
 2. Window evaluated on naive local time, not broker time.             (A5)
 3. No typed tables for orders/positions/trades/round-trips, so the
    decision->execution->reconciliation chain cannot be reconstructed
    after a restart.                                                  (A1)
 4. DR does not cover the stores that hold live trading state;
    SQLite backup reads the db file directly while it is being written,
    so a torn archive can pass verification.

P1 — CONTROL PLANE / OPERABILITY
 5. Dashboard shows no challenge or MT5 surface at all.                (A2)
 6. Dashboard mutations unauthenticated + fake success when offline.  (A3)
 7. 16 unguarded mutating routes incl. payments, users, intake.        (A4)
 8. No persistent account registry: CanonicalState holds one connected
    account; there is no durable (login, server) -> provider/program record,
    so tournament identity must be re-supplied by hand on every boot.
 9. No tournament lifecycle events (bound / started / ended / settled).

P2 — LEARNING / ANALYTICS
10. No account <-> strategy binding, so no per-account strategy attribution.
11. No trade-cycle analytics (win rate, expectancy, profit factor, streaks,
    per-strategy and per-account). There is no round_trip concept anywhere.
12. strategyScore() is recomputed in dashboard adapters.ts from backend
    validation fields; the formula can drift from the backend's.
13. Learning records outcomes (experiences) but nothing closes the loop from
    outcome back into a strategy decision.
